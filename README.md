# Field Research Archive

GitHubリポジトリ名は `field-research-archive`。

「光、空気、海、土を手元にするプロジェクト」のフィールド調査を記録する静的サイト。独立リポジトリのルートにこの一式を置く構成。既存の mountain-plans と共有するデータや依存関係はない。相互リンクが必要になった時点で、各サイトから相手の公開URLへリンクする。

## 確認

リポジトリのルートから `python3 -m http.server 8000` を実行し、ブラウザで `http://localhost:8000/` を開く。ブラウザがJSONを読み込むためHTTPで開く。GitHub Pagesには、このディレクトリの内容を新しいリポジトリの公開元ブランチのルートとして配置する。ビルドは不要。

## 管理単位

| ファイル | 役割 |
| --- | --- |
| `catalog.json` | 調査段階、国・地域、調査テーマ、および掲載するデータセットの登録 |
| `<国・地域コード>-seawater-*.json` | 地点の現在値。地域・行政区分・市区町村は名称で保持 |
| `history.json` | 日付・操作・データセットID・理由。個別変更には地点IDを付与 |

調査段階と地理区分を独立して登録する。日本、アジア、世界はそれぞれ別の調査段階として扱い、全調査横断検索は「調査範囲」を「すべて」にする。アジア・世界に地点データは未収録。海外データを追加するときは国・地域を登録し、各データセットに調査段階・国コード・テーマを割り当てる。件数と絞り込み候補は登録されたデータから算出する。JSONとCSVは画面で表示中の地点を出力する。

## 更新

- 第一次調査の日本候補は `japan_seawater_117_research.html` から全117件を移行。既存の地点ID、名称、所在地、調査状態、出典識別子、河川関連欄を保持した。
- 地点IDは全データセットで一意とし、再利用しない。新規地点には国・地域コードを含む新しいIDを使える。
- 追加・修正時は地点レコードを編集し、履歴に `add`・`update` として変更理由を追記する。差分はGitで確認できる。
- 統合時は統合元のIDと地点レコードを保持し、`lifecycle` を `merged`、`mergedInto` を統合先のIDにする。除外時は `excluded`、復帰時は `active` とし、統合先欄を外す。履歴には `merge`・`exclude`・`restore` を追記する。統合・除外した地点は一覧で表示を切り替えられる。
- 代表位置・水際候補・採水候補は `positions` の別フィールドに保持する。未登録は `null` とし、座標を登録するときは `latitude`・`longitude` を付ける。
- 後続の位置・水際・採水検証報告から、`SEA-04-01` の所在地の不一致と `SEA-16-02` の代表座標を注記に転記した。報告書が参照するCSV・GeoJSONの現物は取得できなかったため、今回の移行対象は初期候補データと上記の注記。

更新後は `node validate.mjs` を実行する。
